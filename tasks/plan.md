# Implementación del MVP staff aprobado

Autorizado por el usuario: login, dashboard y consulta de limpieza con la API existente.

Orden: sesión → dashboard de locales → detalle de equipo → verificación.
Estado único de sesión con Cubit; repositorio Dio exclusivo del recorrido staff para no alterar otros segmentos. Las pantallas previas permanecen en el proyecto; main selecciona el recorrido operativo. Tokens en almacenamiento seguro; sin credenciales incorporadas. Tema Material local con colores existentes, sin descargas de fuentes.

Riesgos: API no disponible en localhost, credenciales pendientes, autorización por titularidad y SDK Android/iOS no detectados. Validar transporte con pruebas controladas y reportar por separado integración/dispositivo real.
